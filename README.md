# TTC Subway Delay Analysis

### One-time R package setup

`uv` manages the Python environment; it does not install R packages. Install the
required R packages once in R or RStudio:

```r
install.packages(c("arrow", "ggplot2", "tinytable"))
```

`run_all.py` checks for these packages before running the final R presentation
scripts. If one is missing, it stops with the installation command rather than
attempting to modify the R installation automatically.

## Research question

**When are TTC subway delay records most likely to be positive, and how does the recorded size of a positive delay vary across the day?**

The paper uses two primary descriptive estimands:

1. The hour-specific proportion of recorded observations for which `Min Delay > 0`.
2. The hour-specific median `Min Delay`, conditional on `Min Delay > 0`.

The analysis uses the official TTC Subway Delay Data published through the City of Toronto Open Data Portal. The current **since-2025** resource is the primary study dataset. The official **2024 annual** resource is downloaded separately and used only as a historical benchmark.

## Reproducibility

The project uses a hybrid workflow: Python handles source acquisition, cleaning, statistical analysis, simulation, and tests; R is used for the final paper presentation, with ggplot2 for the figures and tinytable for the tables. Quarto renders the final PDF. Requirements:

- Python 3.12+
- `uv`
- R with `Rscript` on PATH
- R packages `arrow`, `ggplot2`, and `tinytable`
- Quarto with a working PDF/LaTeX installation
- Internet access for the data-download step

For a new R installation, install the presentation packages once from an R console:

```r
install.packages(c("arrow", "ggplot2", "tinytable"))
```

The R presentation scripts do not download, clean, or statistically analyse the TTC source data. They read the saved outputs produced by the Python workflow. The earlier Python presentation scripts are retained in `scripts/` as reference/alternative implementations, but they are not executed by `run_all.py`.

From the project root:

```powershell
uv sync
uv lock
uv run python scripts/run_all.py
```

The workflow is:

1. `01_simulate_data.py` creates a seeded simulated dataset.
2. Simulated tests validate the known properties of that dataset.
3. `02_download_data.py` queries the official Toronto Open Data CKAN metadata API, discovers the current and 2024 resources, and downloads them to `data/raw_data/`.
4. `03_clean_data.py` creates the Parquet analysis dataset from the downloaded current CSV.
5. Actual-data tests validate the current source schema and derived variables.
6. `04_analysis.py` creates hourly, weekday, monthly, data-profile, data-quality, and mathematical summaries.
7. `06_historical_comparison.py` processes the downloaded 2024 annual file and creates the historical comparison.
8. `07_excel_quality_check.py` creates `outputs/ttc_quality_check.xlsx` for a human-readable check of the downloaded 2024 source.
9. `08_make_figures.R` creates the paper figures with ggplot2 from the saved analysis dataset and Python summary tables.
10. `09_make_tables.R` creates the paper tables with tinytable as LaTeX files.
11. Quarto renders `paper/paper.qmd` using the saved local presentation outputs.

### Important data rule

**Data availability:** The repository includes the downloaded TTC data snapshots used for the analysis. The download script can also retrieve the source data again from the City of Toronto Open Data portal. The analysis dataset is generated from the downloaded source files by the cleaning workflow.

The paper itself does **not** download data. After the downloader finishes, cleaning, analysis, visualization, testing, and Quarto rendering use the saved local snapshot.

The downloader records:

- the official dataset page;
- the resource name and resource ID;
- the actual download URL returned by the official metadata API;
- download timestamp;
- file size;
- SHA-256 checksum.

This makes it possible to identify exactly which source files were used for a particular run.

## Statistical analysis

The paper reports:

- hourly positive-delay prevalence;
- 95% Wilson intervals for the observed hourly proportions;
- hourly median positive delay;
- mean and 95th percentile positive delay as supporting summaries;
- hourly risk differences versus the overall prevalence;
- hourly prevalence ratios versus the overall prevalence;
- a chi-square statistic and Cramer's V as descriptive measures of hourly association;
- weekday and monthly supporting summaries;
- a 2024 versus since-2025 hourly comparison.

These quantities are descriptive. They do not establish that time of day causes delay or measure passenger waiting time.
